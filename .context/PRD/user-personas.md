# User Personas: Web3 QA Learning Hub

## Persona 1: Maria - The Web2 Veteran

### Photo Description
*Woman, early 30s, professional appearance, sitting at a dual-monitor setup in a modern office. Wears glasses, has a focused expression. Background shows testing dashboards and a coffee mug.*

### Demographics
| Attribute | Value |
|-----------|-------|
| **Age** | 32 |
| **Occupation** | Senior QA Engineer at a FinTech company |
| **Location** | Austin, Texas, USA |
| **Education** | B.S. in Computer Science |
| **Experience** | 7 years in QA (banking, e-commerce, SaaS) |

### Goals
1. **Transition to Web3** without starting from zero—leverage existing QA expertise
2. **Understand blockchain testing fundamentals** (wallets, transactions, smart contracts)
3. **Build a portfolio** of Web3 testing skills to apply for blockchain roles
4. **Stay relevant** as her company explores DeFi integrations

### Pain Points
1. **Overwhelmed by jargon**: Gas, nonce, ABI, RPC—feels like learning a new language
2. **No clear learning path**: Scattered YouTube videos and blog posts with no structure
3. **Can't practice safely**: Afraid of losing real funds; testnets are confusing to set up
4. **Existing skills feel useless**: "My Selenium experience doesn't help with MetaMask popups"

### Tech Savviness
- **Adoption Level**: Early majority (waits for tools to stabilize)
- **Daily Tools**: Jira, TestRail, Postman, Selenium/Playwright, Chrome DevTools
- **Devices**: MacBook Pro (work), iPhone, Windows desktop (home)
- **Web3 Experience**: Has MetaMask installed, bought ETH once, never tested a dApp

### Quote
> "I've been a QA engineer for 7 years. I know how to test APIs, databases, and UIs. But when my manager asked me to test our new wallet integration, I had no idea where to start. It's frustrating to feel like a junior again."

## Persona 2: Alex - The Junior Web3 QA

### Photo Description
*Man, mid-20s, casual hoodie, working from a home office with RGB lighting. Multiple browser tabs open, Discord visible on second monitor. Energetic but slightly overwhelmed expression.*

### Demographics
| Attribute | Value |
|-----------|-------|
| **Age** | 26 |
| **Occupation** | QA Engineer at an NFT marketplace startup |
| **Location** | Lisbon, Portugal |
| **Education** | Self-taught + Bootcamp (Web Development) |
| **Experience** | 2 years in Web3 (started during 2021 boom) |

### Goals
1. **Fill knowledge gaps**: Understand *why* things work, not just *how* to click through
2. **Learn automation**: Move beyond manual testing to Playwright + wallet automation
3. **Build credibility**: Prove skills with certifications or portfolio projects
4. **Grow into Senior QA**: Take on more complex testing responsibilities

### Pain Points
1. **Imposter syndrome**: "I find bugs, but I can't explain the transaction lifecycle to devs"
2. **No formal training**: Learned everything from Discord and trial-and-error
3. **Automation gap**: Can write basic Playwright tests but can't handle MetaMask
4. **Fast-moving ecosystem**: Hard to keep up with new chains, wallets, and tools

### Tech Savviness
- **Adoption Level**: Early adopter (uses bleeding-edge tools)
- **Daily Tools**: VS Code, Playwright, MetaMask, Discord, Notion, Tenderly
- **Devices**: Gaming PC (primary), Android phone, mechanical keyboard
- **Web3 Experience**: Active in DeFi, owns NFTs, uses multiple wallets

### Quote
> "I can test our marketplace manually—connect wallet, mint NFT, check it shows up. But when a transaction fails, I just report 'it didn't work' because I don't really understand what happened on-chain. I need to level up."

## Persona 3: David - The Team Lead

### Photo Description
*Man, late 30s, business casual, in a glass-walled meeting room. Whiteboard behind him with sprint planning notes. Confident but concerned expression, holding a tablet with team metrics.*

### Demographics
| Attribute | Value |
|-----------|-------|
| **Age** | 38 |
| **Occupation** | QA Lead at a DeFi protocol |
| **Location** | Berlin, Germany |
| **Education** | M.S. in Software Engineering |
| **Experience** | 12 years in QA, 3 years in Web3 |

### Goals
1. **Reduce onboarding time**: Get new hires productive in weeks, not months
2. **Standardize testing practices**: Create consistent QA processes across the team
3. **Build team capabilities**: Upskill existing members in automation and Web3 specifics
4. **Justify QA investment**: Show leadership the value of quality through metrics

### Pain Points
1. **Hiring is painful**: Web3 QA candidates are rare; most need extensive training
2. **No training resources**: Has to create internal docs from scratch
3. **Inconsistent quality**: Each team member tests differently; no standard approach
4. **Time pressure**: Can't pause sprints to train; needs self-paced learning options

### Tech Savviness
- **Adoption Level**: Pragmatist (adopts proven solutions)
- **Daily Tools**: Jira, Confluence, GitHub, Slack, Grafana, internal dashboards
- **Devices**: MacBook Pro, iPad for meetings, company phone
- **Web3 Experience**: Deep understanding of protocols; manages team but doesn't test daily

### Quote
> "Every new QA engineer we hire takes 3-4 months to understand our stack. I need a training program I can point them to on day one—something structured that covers wallets, transactions, and automation. I don't have time to teach everyone individually."
